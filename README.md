# canon-r5-extensions

佳能 EOS R5 一代固件扩展研究。当前交付是**电脑端只读文件指纹工具、QEMU-EOS 离线构建与合成测试、源码调查记录**，尚未实现任何相机功能，也没有可刷写文件、安装器或 `autoexec.bin`。

遵循最小改动、证据先行、鲁棒性优先。不是 Canon 或 Magic Lantern 官方项目；机主实际固件版本尚未确认。

## 三个目标的现状

| 目标 | 已有依据 | 尚缺什么 |
| --- | --- | --- |
| 自定义电子快门声音 | ML 有通用音频代码，但包含录音干扰警告 | R5 的扬声器播放接口、曝光事件和安全调用上下文均未验证 |
| 肩屏曝光倒计时 | Canon 已支持 B 门计时器，并在肩屏显示曝光经过时间 | 肩屏独立显示路径、已设时长与实际曝光状态的可靠读取方式 |
| 全画幅 4K 50/60p 真正超采样 | 官方 8K RAW 上限约 30p，普通 4K 支持 50/60p | 高分辨率 50/60p 读出、ISP、内存带宽、供电散热和编码整条路径的证据 |

目前没有证据把第三项认定为“改一个软件开关即可”。R5 C 的能力也不能直接证明 R5 的整条处理链可用。详细依据、固定版本源码链接与风险见 [RESEARCH.md](RESEARCH.md)。

## 使用离线工具

只需 Python 3.10+ 和标准库；当前已在 Windows / Python 3.12.14 自测。把需要研究的文件复制到电脑本地，用电脑运行以下命令，不需要连接相机。

```text
python -B inspect_firmware.py "path/to/firmware.FIR"
python -B inspect_firmware.py "path/to/firmware.FIR" --expect-sha256 <64位十六进制SHA256>
```

工具输出 JSON，包括文件长度、SHA-256、可选的哈希匹配结果。**它不解析 FIR、不识别机型或版本、不验证 Canon 数字签名**；文件名、扩展名和其中的字符串均不能作为放行依据。非空但已损坏的文件也能得到指纹，因此输出指纹不代表文件有效。

- `camera_compatibility` 等验证字段始终为 `unverified`。
- `safe_to_flash` 始终为 `false`，含义是本工具从未批准刷写，并非断言文件一定有害。
- 退出码 `0`：完成指纹计算，且未提供预期哈希或哈希匹配；`1`：哈希不匹配；`2`：参数、文件或读取错误。**退出码 0 不代表可以安装。**
- 预期哈希应来自另行核实的来源。对同一文件自己算两次，只能检查一致性，不能证明来源可信。

工具以 `rb` 模式分块读取，拒绝空文件、目录和设备输入；对读取前后可见的文件替换、大小或修改时间变化报错。它不能防御刻意恢复元数据的并发篡改，也不保证网络文件系统上的快照一致性。请使用稳定的本地副本。

不提供输出文件选项，以免覆盖固件。需要保存报告时，确保 shell 重定向目标是**另一个文件**；shell 会在程序启动前截断目标文件。访问时间可能由操作系统更新。报告不包含输入路径、固件内容或从中提取的机身信息。

## 自测

```text
python -B -m unittest discover -s tests -v
```

12 项测试通过，使用的全是临时合成数据，没有 Canon 固件。覆盖标准 SHA-256 向量、匹配/不匹配、非法哈希、空文件/不存在/目录/设备、模拟访问拒绝与读取故障、跨块输入的字节和修改时间保留、中文路径，以及读取中截断/追加/改写。伪造 R5 文件名和版本字符串、提供匹配哈希，都不能让输出变成“可刷写”。

## QEMU-EOS 离线环境

已从固定上游提交构建 Windows 版 QEMU-EOS，并用自写 ARM 指令在 R5 模型中通过正常运行、故意错误和死循环超时三项基础测试。没有 R5 ROM，**没有启动 Canon 固件或验证相机功能**。额外 RAM 读/写日志检查均失败；不能用日志缺失来证明没有危险访问。

构建脚本、最小 Windows 兼容补丁、测试用法、已知模型缺口与失败依据见 [QEMU.md](QEMU.md)。动态指令插件关闭，尚不能套用依赖插件的上游研究流程。

## 本次风险与下一步

文件指纹工具只读电脑端普通文件；合成 ARM 程序只在模拟器中执行并读写临时虚拟内存。测试未连接相机，也未访问物理存储或修改真机启动标志、NVRAM 和闪存。没有验证任何真机恢复方法；模拟器的启动配置、外设占位及日志缺口可能漏掉导致真机变砖的行为。这些测试**不能证明未来相机补丁不会变砖**。

下一步先确认机身菜单里的完整固件版本，再核对对应的 Canon 官方下载文件及来源，开展该版本的离线分析。不要为匹配现有 ML 代码而直接降到 1.5.2。启动与恢复路径有依据之后，才适合研究最小的相机端实验；先调查已有 B 门显示路径，再评估音频，视频模式另行取证。
